## 2. 本次已修改

### 患者关联

- 新问诊、新病历通过共享 `patientService.getById(patientId)` 精确查询，返回 ID 也必须一致。患者 ID 原样保留，不转数字、不剪裁、不按姓名匹配。
- 创建时的姓名来自查询结果，忽略调用方伪造或过时的姓名。查询或保存失败不更新缓存、业务记录或成功审计。
- 患者改名后，问诊和病历的当前身份、全局病历搜索读取共享档案；已有 `patientName` 保留为历史快照并明确标注，导出同时带 ID、当前姓名及快照姓名。
- 缺失档案时，历史消息和文书仍可读；当前档案不可用的状态明确显示，新发送、新建病历和临床编辑禁用。不会回退第一位患者。
- 无效会话/病历直达链接明确显示找不到记录，不展示另一条记录的编辑器。
- 病历页生成演示 AI 草稿时显式传当前病历的 `patientId`，修复共享选中患者不同步导致串用身份的问题。

### 登录认证

按已确认的协议新增可配置适配器：

| 接口 | 调用方式 |
| --- | --- |
| POST /api/auth/login | JSON `{ account, password }`，不提交前端选择的角色 |
| GET /api/auth/me | Bearer 登录返回的 token，采用服务端返回的身份 |
| POST /api/auth/logout | Bearer token；本地退出独立于网络通知结果 |

- 密码登录成功后继续验证 `/me`，两次身份 ID 必须一致，验证前不进入已登录状态。
- 公开 `currentUser.id/account/name/role`。数字 ID 仅接受安全正整数并转字符串；字符串 ID 保持原值。真实用户不套用演示医生的科室、职称。
- API 会话使用独立存储键 `doctor-platform-api-session-v1`，并绑定规范化的服务器地址，不读取演示令牌。更换后端地址须重新登录。
- 页面刷新后通过 `/me` 恢复；失效、停用等401响应会清除当前身份。网络、配置和响应错误明确显示，不静默切回演示模式。
- 真实模式禁用未接入的短信、人脸入口和演示角色选择；不宣称验证码投递、注册或人脸服务已完成。
- 退出同步清理本地身份并丢弃共享内存缓存；旧登录/恢复请求不能在退出后恢复旧账号。演示模式的持久数据仍为明确标注的共享虚构数据。
- 当前后端 logout 不撤销已签发 JWT，本轮保留“当前浏览器退出”的既有语义，没有擅自改服务端撤销策略。

## 3. 配置与实际运行范围

默认 `.env.example` 的 `VITE_API_BASE_URL` 为空，当前5173演示页面继续可用，之前保存的本地数据未删除或上传。

要接入已经启动的认证后端：复制 `.env.example` 为 `.env.local`，设置真实服务根地址并重启 Vite。例如（仅示例地址，不表示本机已运行此服务）：

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:3000
```

不要在 `VITE_*` 中放数据库密码或 JWT 签名密钥；这些变量会进入前端包。

**本仓库当前工作分支尚无患者/问诊 HTTP 适配器。** 配置真实认证后，登录成功进入 `/connection`，显示服务端身份及诊疗服务尚未接通的状态。该模式不会载入或写入本地模拟患者、问诊、病历，不会把浏览器保存误报为服务端保存。只有统一患者接口、访问范围和真实诊疗适配器完成联调后，才能接通真实诊疗工作区。

目前验证了适配器单元测试及隔离浏览器的模拟 HTTP 协议测试；**未收到可用后端地址和联调账号，未执行真实 MySQL/JWT 服务端联调**。

## 4. 可直接验收

- [ ] **I01 患者改名**：在 Patient Information Management 修改姓名，回到问诊/病历。当前姓名更新，患者 ID 不变，原姓名仍按快照显示。
- [ ] **I02 新患者链路**：新建患者，Demo Tools 选择该患者创建问诊，保存小结并创建病历。三处使用新患者同一完整 ID。
- [ ] **I03 精确定位**：从问诊或病历的 Open Patient Profile 进入档案，定位对应患者及其分页，不落到首条患者。
- [ ] **I04 历史与导出**：改名后导出问诊或病历，分别看到患者 ID、当前姓名、创建文书/问诊时的姓名快照。
- [ ] **I05 无效链接**：在独立测试页用不存在的 `?session=...` 或 `?record=...`，应显示找不到记录，不能对默认记录执行写入。
- [ ] **I06 缺档案**：在隔离测试数据中移除患者档案后打开已有问诊。历史可读，缺档案状态明确，不显示另一人的摘要，不允许新建病历。
- [ ] **I07 真实登录模式**：配置已启动的后端地址，密码登录使用后端账号，界面没有演示角色选择；SMS/Facial入口禁用，登录后身份来自 `/me`。
- [ ] **I08 会话恢复和失效**：刷新后重新验证 `/me`；无效/过期凭据回登录页，不进入本地模拟工作区。退出后再访问受保护页面要求登录。
- [ ] **I09 模式隔离**：存在旧 demo token 时启用真实模式，仍必须后端登录；真实模式不能通过直接访问 `/consultation` 或 `/records` 绕到本地患者数据。
- [ ] **I10 账号边界**：真实模式退出并登录另一账号，只显示新身份。真实登录错误或网络错误不生成 demo token，不假报成功。

I07–I10 的真实服务验收需在队友后端启动并提供测试账号后执行；本轮已用模拟 HTTP 覆盖相同前端流程。
