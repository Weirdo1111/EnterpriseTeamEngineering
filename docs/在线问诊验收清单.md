# 在线图文问诊验收清单

适用：曾成负责的医生端图文问诊，本地接口适配器版本。建议按编号依次检查，通过后勾选，失败时记录编号、操作、实际结果和截图。

患者 ID 与登录接口的新增验收项见 [接口对接结果与待联调](./接口对接结果与待联调.md) 的 I01–I10。默认仍为本地演示。配置后端后，认证、普通病历及 AI 可调用服务端；本清单的患者消息、图片和问诊关联病历仍保存于浏览器。

## 验收前准备

- 启动项目：在仓库目录运行 `npm run dev`，打开 http://127.0.0.1:5173/consultation 。如果已有服务，直接刷新当前页面。
- 以 **Physician · Dr. Riley Lin** 登录。未配置后端时使用演示角色；若已配置后端，使用有效医生账号，验收数据仍须为虚构资料。
- 使用同一浏览器、同一地址验收；`localhost` 与 `127.0.0.1`、不同端口、不同浏览器的数据不共用。不要清除网站数据。
- 准备一张虚构内容的 JPG、PNG 或 WebP 图片，大小不超过 5 MiB，像素不超过 2400 万。
- 测试文字建议包含独有标记，例如 `验收-A01`。数量按操作前后变化核对，不要求与种子数据数量一致。
- **Demo Tools 是本地验收工具**：由你模拟患者的新请求和回复，不会连接真实患者或向他人发送消息。

## A. 请求、队列和未读

- [ ] **A01 新建请求**：进入 Online Consultation → Demo Tools → New request，选择患者，填写主诉 `验收-A01`、首条消息，点击 Create Demo Request。预期：成功提示，左侧新增 Waiting 会话、未读 1 条，原先选中的会话不被替换，输入表单清空。
- [ ] **A02 必填检查**：不选患者或不填主诉/首条消息直接创建。预期：对应字段出现提示，不新增会话。
- [ ] **A03 请求保存**：关闭工具、刷新页面。预期：A01 请求仍在，未读不会仅因刷新被自动清除。
- [ ] **A04 队列筛选**：使用左侧 Name, ID, or complaint 输入 `验收-A01`，切换 Queue status 的 Waiting / In Progress / All。预期：仅筛选左侧待处理队列；输入无匹配文字显示空状态，Clear queue filters 恢复列表，聊天内容不因此丢失。
- [ ] **A05 已读保存**：点击新请求，或点击其 Read latest，刷新。预期：未读标记消失且不回弹，会话仍为 Waiting。点击右上通知铃铛，显示当前实际数量。
- [ ] **A06 接诊**：点击 Accept 后刷新。预期：状态为 In Progress，队列筛选数量更新。

## B. 图文交流

- [ ] **B01 医生文字**：关闭 Demo Tools，在左侧选择刚接诊的 In Progress 会话。向下滚动整个页面（不要只滚动聊天记录内部），在中间聊天记录下方找到提示为 `Enter a consultation reply or follow-up advice` 的输入框，输入 `医生验收-B01`，点击旁边的 **Send**。预期：消息出现在聊天右侧，标注 **Physician** 和时间；发送成功后输入清空，刷新仍可看到。Demo Tools → Patient reply 只用于 B06/B07 的患者模拟回复，不是医生发送入口。
- [ ] **B02 空消息和快捷键**：只输入空格且无图片，不能发送；输入文字后按 Ctrl + Enter。预期：发送一条消息，不重复。
- [ ] **B03 图片预览**：Add Image 选择图片，检查预览；Remove image 后重新选择；Replace Image 更换。预期：预览与选中文件一致，发送前不会进入历史消息。
- [ ] **B04 图片消息**：分别测试只发图片、图片带说明文字。预期：缩略图、文件名、尺寸与说明正确；刷新后仍在；点击缩略图可放大并下载原图。
- [ ] **B05 无效图片**：尝试非 JPG/PNG/WebP 或超过限制的图片。预期：明确错误提示，不插入消息；原文字与已有草稿图片保留。
- [ ] **B06 模拟患者文字**：Demo Tools → Patient reply，确认显示的是当前患者和会话，输入 `患者验收-B06`，点击 Simulate Patient Reply。预期：患者一侧新增消息、未读数增加；关闭工具点击 Read latest 后清零。
- [ ] **B07 模拟患者图片**：Patient reply → Add patient image，选择图片后发送，可附文字。预期：患者图片与医生图片一样可保存、预览和下载，不显示成医生消息。
- [ ] **B08 跨会话草稿**：在当前会话输入未发送文字并选图片，切换另一条会话，再返回。预期：各会话草稿独立，文字和图片不串患者；队列显示 Unsaved draft。

## C. 问诊小结

- [ ] **C01 创建小结**：点击 Consultation Summary。预期：主诉从本次请求带入，评估和建议没有自动生成内容；填写 Consultation notes，可补 Assessment、Advice / plan、Follow-up，点击 **Save**。保存成功后面板自动关闭，提示 **Summary saved**，页面上的小结卡片更新内容、医生姓名、保存时间和 **Saved**；再次打开可继续编辑。
- [ ] **C02 小结必填**：清空主诉或 Consultation notes 后点击 **Save**。预期：提示必填，面板保持打开，其他输入保留，原已保存小结保持不变；补齐后再次点击，成功保存并关闭。
- [ ] **C03 小结保存与草稿**：Save 成功后刷新，内容仍在；重新打开并修改小结，只点击 **Close**，再打开时未保存内容仍在，显示 **Unsaved changes**；Discard changes → Keep editing 保留输入，确认 Discard changes 才恢复已保存内容。
- [ ] **C04 草稿保护**：小结有未保存改动时点 End Consultation 或 Export Current Conversation。预期：提醒先保存或丢弃，并打开小结编辑，不提前结束或导出；点击 **Save** 成功关闭后，可重新点击结束或导出。

## D. 历史检索和导出

- [ ] **D01 统一记录入口**：页面顶部只有 Consultation Records 作为问诊记录入口；顶栏只显示 Online Consultation。预期：不再同时出现患者全局搜索和旧 Search Records / History 重复入口。其他模块原有全局搜索仍在。
- [ ] **D02 搜索范围**：在 Consultation Records 中分别搜索患者名、患者/会话 ID、B01/B06 的消息标记、图片文件名、小结独有文字。预期：返回对应会话；小结命中有明确说明，消息命中可直接定位。
- [ ] **D03 日期和状态**：组合 All / Waiting / In Progress / Completed、关键词和今天的起止日期。预期：消息按发送日期、小结按最近保存日期匹配；起始日晚于结束日提示错误。旧样例若只有时分而无完整日期，不纳入日期筛选。
- [ ] **D04 定位和空结果**：点击某条命中消息，预期：进入正确会话并定位、高亮该消息；Latest message 返回末尾。无结果时 Clear filters 恢复记录。检索期间各会话未发送草稿保留。
- [ ] **D05 导出**：点击 Export Current Conversation。预期：下载 TXT，包含当前患者/会话、已保存小结、文字和图片文件名/尺寸；无其他患者内容、无未提交草稿。图片原文件需在图片查看器中单独下载，TXT 不嵌入图片字节。

## E. 病历草稿衔接

- [ ] **E01 创建关联病历**：先保存小结，点击右侧 Medical Record → Create Record Draft。预期：进入 Medical Records，明确标注 From saved consultation summary，主诉、问诊记录、人工评估、计划和随访按小结带入；未填写评估时诊断为空，不自动添加医嘱，不标为 AI 生成。
- [ ] **E02 编辑和刷新**：修改 Present Illness / Preliminary Diagnosis，点击 Save Draft 后刷新。预期：停留在同一病历，修改保留；保存前离开会提醒，Keep editing 不丢输入；重复点击左侧当前病历也不清空未保存编辑。
- [ ] **E03 不重复、不覆盖**：View Source Consultation 返回源问诊，再点 Open Linked Record。预期：打开相同病历，不新增。随后修改并保存源小结，再打开病历：显示源已更新提示，病历里人工修改的内容保留，需要医生手动核对更新。
- [ ] **E04 关联病历审核**：补齐主诉、现病史和诊断，Submit for Review。预期：变为 Pending Review，医生不能再编辑或审批；以 Senior Physician 登录，可写审核意见、退回修改或批准，批准后可 Archive Record；刷新后状态保留。此项验证仅针对从本模块创建的关联病历。

## F. 结束、权限和页面保护

- [ ] **F01 结束确认**：返回正在进行的会话，End Consultation → Keep chatting。预期：仍可回复；再次结束并确认后，离开待处理队列，消息和小结变只读。若还有未发送文字/图片，结束前明确提示将丢弃这些草稿。
- [ ] **F02 历史复查**：刷新 → Consultation Records → Completed → 打开该会话。预期：完整消息、图片、小结可查、可导出；无法继续发送或修改小结；Demo Tools 中不能给它模拟新回复。
- [ ] **F03 离页和退出保护**：在另一条活动会话输入未发送文字/图片或未保存小结，点击侧栏其他模块或 Sign out。预期：出现 Leave with unsaved changes?；Stay on this page 保留输入且仍处于登录状态；Leave and discard 才离开。刷新/关闭标签由浏览器显示原生未保存提示（需有过页面交互）。
- [ ] **F04 管理员只读**：以 System Administrator 登录，打开问诊及关联病历。预期：可查看记录、图片、小结和导出；不能接诊、发消息、模拟患者请求/回复、改小结、创建或编辑临床病历。前端角色演示不等于服务器权限认证。
- [ ] **F05 窄屏操作**：缩窄浏览器，检查队列、聊天、图片、小结和 Demo Tools。预期：没有整页横向溢出，抽屉标题和关闭按钮不被顶栏遮挡，内容可滚动。

## 异常场景（已由开发测试覆盖，可选复验）

- [ ] **X01 保存失败**：模拟 localStorage 写入失败。预期：不显示保存成功、不修改原持久记录；文字、图片、小结或病历表单保留，可在恢复后重试。小结保存失败时面板保持打开并显示错误，点击 **Retry Save** 重试；仅在保存成功且没有新的未保存改动时自动关闭。
- [ ] **X02 重复提交**：对相同请求/消息标识重试。预期：不重复新增会话/消息，不重复增加未读；标识对应不同内容时拒绝。
- [ ] **X03 数据损坏**：在独立测试浏览器修改存储为非法内容后刷新。预期：显示读取错误，不覆盖原数据；修复内容后 Retry loading / Retry loading records 可以恢复。请勿在自己的演示数据上破坏性测试。
- [ ] **X04 老数据兼容**：加载此前保存的版本 1/2 聊天，操作后升级至版本 3。预期：原文字、图片引用和状态保留，已有小结也不会在后续发送、接诊、结束中丢失。

## 范围与仍需联调的项目

老师《Doctor Work Platform - User Requirements(1).pptx》第 5 页，以及《医生用户需求.docx》的“在线问诊服务”要求接收请求、图文/视频交流、保存、检索和导出。本清单完成的是**当前不依赖统一接口的图文问诊与病历交接**。

以下不标记为已完成：

1. 真实患者端发起请求、跨设备实时聊天、服务端数据库/文件保存、断线重连和跨设备同步。
2. 视频问诊、双方音视频连接与录音录像。PPT 有此要求；当前未接视频服务，Demo Tools 不能替代视频验收。
3. 问诊的患者授权范围、访问审计持久化、备份恢复和生产数据安全。服务端密码认证已整合，但不代表问诊已接入后端；问诊审计仍为内存演示。
4. 普通病历和 AI 助手的后端能力沿用 main 的实现，需单独联调；问诊关联病历使用独立本地存储，本清单 E04 不替代普通病历的医嘱及审核验收。

浏览器存储仅用于课程开发演示。请使用虚构资料。关闭页面会丢弃明确标记为未保存的草稿，已保存数据保留；清除网站数据会删除本地聊天、图片和关联病历。
